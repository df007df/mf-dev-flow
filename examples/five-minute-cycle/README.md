# 五分钟最小闭环示例

这是一个可公开运行的合成项目，用一个小而完整的场景说明 `mf-dev-flow` 的用途。它不是模板项目，也不代表真实产品或用户数据。

## 用户场景

旅行者准备出行时，需要快速核对已经完成的事项。需求是：

> 在旅行清单中增加“仅看已完成”筛选；默认仍显示全部项目。

对应的示例功能点、验收用例和阶段状态已经写在 [`.mf-dev-flow/`](.mf-dev-flow/) 中。可交互的目标页面在 [`app/index.html`](app/index.html)。

功能、case、页面区域与真实截图的逐条映射见 [`cases.md`](cases.md)，其中先展示包含验收 case 卡片与功能卡片的看板分组区块，再分别展示页面状态。

## 两分钟打开观察台

从本目录执行：

```bash
pnpm --dir ../../dashboard install
node ../../scripts/mf-dev-flow.mjs dashboard
```

打开 <http://127.0.0.1:4173/>，重点查看：

- **功能点看板**：目标是“仅看已完成项目”，写入范围只有 `app/index.html`。
- **功能点分组列表**：两条最终验收用例说明默认状态与筛选状态。
- **运行历史**：本例保留的是“计划完成、等待真实交付”的状态，避免把合成样例伪装成已完成生产交付。

## 五分钟演练

1. 用浏览器直接打开 `app/index.html`，确认默认显示三项行程。
2. 点击“仅看已完成”，确认只保留两项已完成行程；再次点击可返回全部。
3. 回到观察台，打开“仅看已完成项目”的详情。比较用户结果、写入边界和验收用例是否覆盖刚才的交互。
4. 假设由另一个代理实现此需求：它只能改 `app/index.html`，并要在交付阶段记录真实浏览器验证。范围以外的改动不应被静默归因。

这个小场景说明了流程的实用点：功能目标、允许修改的地方和“什么算完成”在实现前就已经明确。

## 示例数据边界

`.mf-dev-flow/` 下的数据是专门提交的公开 fixture，用于驱动看板截图和文档，不是真实运行状态。真实项目的 `.mf-dev-flow/` 仍应保持在本地且不提交版本库。

`screenshots/` 中的图片来自本示例页面的真实浏览器运行，专用于说明 case 与页面结果的对应关系；它们不表示该合成任务已经通过交付阶段门禁。
