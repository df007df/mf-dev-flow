# 原型分析报告格式 v2

## 数据与文档边界

原型分析的真源是 `.mf-dev-flow/prototype/catalog.sqlite` 和当前批次 `analyses/<批次 ID>/index.sqlite` 中的结构化记录。记录在命令边界上表现为 JSON 对象，但看板不把 JSON 拼成页面，也不直接读取 SQLite。

`modules/prototype/core/report.js` 按结构化记录确定性生成批次 `report.md`；`modules/prototype/cli.mjs` 再合入用户问题、需求和语义变更，原子写入唯一当前报告 `.mf-dev-flow/prototype/report.md`。成功验收及已验收结论的语义变更会自动物化这份派生报告，`prototype report` 只用于显式重建。看板先调用只读 `prototype document` 校验内容指纹和格式版本，再读取这份 Markdown，由 `MarkdownContent` 渲染。

`brief.json`、`audit.json` 是派生的机器审计产物，不是看板报告正文，也不能作为第二份报告真源。

运行态 `runtime-only` 报告必须包含固定边界声明：`证据等级：运行态覆盖。本报告只描述已实际观察并归档证据的行为；不声明源码、隐藏分支或未观察状态的完整性。` 该声明不是验收替代物；它要求报告和读者都把结论限制在实际截图、追踪和结构化观察覆盖的范围内。`source-and-runtime` 报告不写入这句运行态专属声明。

小程序报告边界：runtime-only 报告不代表源代码审查。它仅汇总已归档的模拟器观察；不可观察页面、分支和未完成项必须继续显示为未完成，不可用截图数量替代覆盖判断。

iOS 报告边界：runtime-only 报告不代表源代码审查。它仅汇总已归档的模拟器观察；不可观察界面、分支和未完成项必须继续显示为未完成，不可用截图数量替代覆盖判断。

## 固定章节顺序

新报告格式为 `2`；版本与兼容集合以 [报告格式常量](../../modules/prototype/core/report-format.js) 为准，现有 v1 由看板兼容读取。这里固定的是报告协议的通用骨架，不是九个业务模块，也不限制业务分组数量。具体分组、页面、角色、状态、问题和回答全部来自结构化分析记录；生成器不得写死首页、个人页或任何项目业务名称。某个通用章节暂无数据时保留明确的空状态，不用业务内容改变报告结构。

当前完整报告必须且只能按以下 H2 顺序生成：

1. 覆盖与未覆盖
2. 用户流程、页面与状态
3. 截图与证据索引
4. 待确认问题
5. 未完成与无法观察
6. 文件遍历索引
7. 更新记录
8. 用户问题、回答与需求
9. 语义变更与回答历史

用户流程使用 H3 表示分组，H4 表示页面或状态。分组按 `group.order`、入口和节点顺序稳定排列。动态字段按纯文本转义并折叠换行，不能注入新的标题、表格或图片。

## 截图格式

页面或状态的主证据，以及该节点每条带截图的边证据，必须在以下三列表格中显示，截图、操作结果和证据追踪保持在同一行：

| 截图 | 操作与结果 | 证据 |
| --- | --- | --- |
| `![页面或状态](.../screenshots/<内容哈希>.png)` | 操作：…；结果：… | 证据 ID · 查看追踪 |
| `![edge-ID 截图](.../screenshots/<内容哈希>.png)` | edge-ID：操作、输入类别、目标状态、结果与复现动作 | 证据 ID · 查看追踪 |

正文中的 Markdown 图片只能出现在表格行内。没有截图的未完成边保留文字说明；有截图的边不得降级成“截图/追踪”文本链接。全局“截图与证据索引”继续使用链接，不重复渲染图片。当前报告只引用仍被有效结构记录引用的证据，已替换图片只留在历史归档。

## 发布与兼容门禁

生成器先写临时文件，再由 `assertPrototypeReportFormat` 校验标题、章节顺序、固定表头、图片位置、截图归档路径和禁止输出的审计章节；校验通过后才原子替换报告。完整报告追加语义章节后再次校验。

格式版本同时写入报告元信息、批次 `brief.json`、生成命令结果和 `prototype document` 响应。新生成报告使用 v2；看板兼容显示 v1，并将其中每条完整的边截图链接即时提升为图片表格。无版本或未知版本的报告必须重新生成，不能进入渲染。修改章节、层级、截图布局或渲染约定时必须升级版本、更新本文件、生成器、读取端和回归测试。
